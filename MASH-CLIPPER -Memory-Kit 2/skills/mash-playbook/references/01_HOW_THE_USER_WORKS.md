# 01 · How this user works (read first)

## Who they are
- A professional video editor: short-form reels, YouTube edits, podcast clips, ads, for clients and their own channel.
- Mac user. Tools: Premiere Pro, After Effects, Claude Code (desktop app, often controlled from the phone through Remote Control).
- Speaks Hindi / Hinglish. Most source videos are Hindi or mixed Hindi-English. On-screen text is written in the language actually spoken (Roman Hinglish for Hindi speech) unless told otherwise.
- Dictates prompts by voice (Wispr Flow), so product names and people's names arrive garbled. See `08_PROMPT_LIBRARY_AND_GLOSSARY.md`.
- Often watches results on the phone. Always deliver a phone-safe preview (see `09`).

## How they like to work
1. **Short prompt, high expectation.** They give a rough direction ("make 3 clips", "use the documentary style") and expect you to find the best option yourself. Take initiative; do not ask for things you can decide.
2. **Step-by-step with approval gates.** Raw clips → style → PNG storyboard → 720p preview → 4K. Never skip a gate, never render before the storyboard is approved, never do 4K before the 720p is approved. At each gate show real files, then stop.
3. **Visual storyboard, always.** Full-screen PNG frames (1080x1920) taken from the real build, one per beat. Never a text-only storyboard, never an animatic MP4.
4. **They repeat themselves, on purpose.** "I already said it 1,000 times, I will say it 2,000 times." Every correction is a permanent rule. If you see the same mistake twice, you have failed the memory. Read `07_MISTAKES_NEVER_REPEAT.md` before every build.
5. **Quality bar = "no glitch, ever".** Smooth transitions, smooth text, no overlaps, no flashes, no jumps. Check every build 2-3 times: beat frames, every transition midpoint, final frames. Do not say it is ready until you have looked at the frames.
6. **Wait for the full feedback batch.** If they say they are sending notes one by one, collect them, do not start editing until they say go.
7. **Do routine steps without asking.** Clearing a composer, toggling a switch, navigating, re-cutting a join. Only ask for things that spend money/credits, delete their files, publish, or are genuine creative choices.
8. **Re-render only what changed; render only the deliverable.** If they ask for 4K, do not also render 1080p. For a local fix, re-render only that section.
9. **Save their limits.** Use snapshots for checks, not full renders. No wasted renders, no wasted generations.
10. **Always say where the final is.** Exact folder + file name, reveal in Finder (`open -R`), give an ETA when a long render starts.
11. **Away mode.** If they say they are leaving: show the storyboard, and if there is no reply in 5-10 minutes build the final so it is ready when they return.

## How to talk to them
- Plain words, short. Lead with what is done and where the file is. No jargon, no long explanations of internals.
- When they are on the phone, files over ~30 MB cannot be sent in chat: send a small phone copy and give the path of the full one.
- Tell the truth about what was and was not verified ("I checked 28 stills, I have not watched it at full speed").
- If a request is ambiguous in a way that changes the work (e.g. which person is "the host"), ask ONE short question with options, then continue.
- Never invent facts, numbers or quotes. On-screen words are the speaker's exact words.

## Money / credits
- Never spend paid generation credits (image/video AI) without an explicit yes and a cost estimate. Prefer "Unlimited" modes (Seedream with the Unlimited switch on = 0 credits). Verify the transaction log shows 0 credits afterwards.
- Describe styles in prompts, never brand names (an "Apple style" prompt bakes the logo into the image).
